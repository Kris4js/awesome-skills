# Compact Floating Panel

构建可嵌入任意业务的紧凑工具浮窗：浅绿中性色、细边框、小字号、固定头尾、独立滚动内容。默认是**网页内浮窗**，不是浏览器原生侧边栏，也不是新浏览器窗口。

## 执行流程

1. **确认宿主和范围。** 阅读目标项目入口、样式与生命周期约定。默认使用 Shadow DOM 隔离；已有 React/Vue 项目沿用框架，组件仍挂在隔离根。只有用户明确要求原生 sidePanel 时才改用该容器。完成条件：明确挂载点、状态归属与需要的组件。
2. **搭建窗口壳。** 读取 `references/design-system.md` 的“窗口与结构”。复用 `assets/panel.css`，在 ShadowRoot 内加载，窗口外层使用 `.fp` 包裹。标题栏、内容区、底栏是同级；使用 `references/markup.md` 的结构起步。完成条件：400px × 80vh 的浮窗、头尾不随内容滚动、窄屏不越界。
3. **按需组合组件。** 读取设计规范中所需组件。以 CSS 文件为 token 与选择器的唯一数值来源，扩展业务类名而非复制插件业务 ID。正文使用11px，表单/分段选项12px，标题16px；长列表不继承宿主页面字号。完成条件：所有需求组件都有空、加载、成功、错误、禁用状态中适用的状态。
4. **接入交互。** 依照设计规范“交互契约”实现 Pointer Events 拖动、边界约束、收起/恢复、键盘移动、清理监听。任务状态独立于显示状态，收起不卸载业务组件。完成条件：拖动按钮不会误触、隐藏后结果保留、重复挂载不生成多个窗口。
5. **接入真实业务。** 默认没有采集、评论、导出或网络副作用。扩展需要特权 API 时由后台明确操作桥接，页面组件只接收数据与动作。普通网页不引入 chrome API。文本以 textContent/框架转义输出。完成条件：样例数据已替换为真实数据源，所有操作都有真实行为或明确禁用说明。
6. **验证。** 至少检查375×700、1280×900、暗色主题、键盘操作与 reduced-motion。测试长标题、长列表、长链接、空结果、操作按钮换行；核对宿主样式未污染窗口、窗口 CSS 未污染宿主。完成条件：无横向页面溢出，底部操作始终可达，焦点可见，收起恢复不丢状态。报告执行过的检查及未验证项。

## 必须保持的设计原则

- **密度分级**：11px 主体内容，10px 元信息，12px 控件，16px 窗口标题，24px 统计数字。9px 仅可选次要说明，不用于关键操作。
- **轻边框代替厚阴影**：组件主要靠1px边框与7–10px圆角分组，仅窗口使用明显阴影。
- **单一主动作**：底栏一个绿色主按钮，其余中性按钮；按钮较多时主按钮独占第一行。
- **状态可解释**：圆点必须配文字；失败详情可读，不仅靠颜色或悬停提示。
- **收起不是结束**：显示状态与任务状态分离。刷新/导航会丢失内存状态时明确告知用户。
- **通用与业务分离**：不复制京东 URL、SKU、评论数上限、RPC、Word 字体规则等业务内容。

## 交付说明

交付窗口文件、业务接入点、运行/验证方法及未完成项。本技能是实现规范和样式资产，不自动提供拖动控制器或业务逻辑；复制 CSS 不等于交互完成。优先适配现有项目，不额外引入 UI 框架。
