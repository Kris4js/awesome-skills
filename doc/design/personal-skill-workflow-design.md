# 个人 Skill 工作流设计

状态：本仓库第一版设计。使用方法见[工作流指南](../usage/matt-pocock-workflow.md)，安装见[快速开始](../zh/quickstart.zh-CN.md)。这是一份本项目的设计，不是上游 Skill 的替代版本。

## 背景

本仓库已经收录固定版本的 Matt Pocock 系列和前端 Skill，但早期首页主要解释“应该怎样使用”，没有提供足够直接的安装命令。另一方面，试用单个 Skill 被推进成了多轮项目配置确认，增加了流程负担。

这次要解决两个具体问题：读者能从首页完成首次安装；维护者能按实际任务运用 Skills，而不是为 Skills 维护一套仪式。

## 目标与非目标

**目标**

- 英文 README 是对外首页，中文版本具有相同的入口、安装方式和状态说明。
- `doc/usage/` 回答怎么安装、怎么选、怎么验证；`doc/design/` 解释为什么这样组织。
- 使用 Matt Pocock 的聚焦工作流、共享术语和按需文档方法，形成适合这个仓库的约定。
- 文档中的安装示例可执行、可测试，且不覆盖既有安装。

**非目标**

- 不克隆 `best-project-memory` 的四文件记忆体系，也不引入记忆数据库或自动整理脚本。
- 不自动安装全部 Skills、不宣称复制成功就是运行有效。
- 不为文案修订强制创建 Issue、tickets 或多代理审查。
- 不改写第三方快照来迎合本仓库流程。

## 核心取舍

| 决策 | 理由 | 代价 / 何时重看 |
| --- | --- | --- |
| 系列与工程领域并存 | 保留 Matt Pocock 的组合关系，其他内容按任务易于找到 | 分组增加时，优先改导航而非搬动上游结构 |
| 复制单个 Skill，不自动同步 | 安装版本可控，支持用户本地调整 | 更新需人工比较；出现频繁重复操作时再考虑工具化 |
| 英文首页 + 中文概览/快速开始 | 对外易读，同时服务中文维护者 | 双语存在漂移成本，由同改约定和示例测试降低 |
| 短 AGENTS + 按需文档 | 常驻指令只承担导航和硬边界 | 指针需要清晰说明何时阅读 |
| 单一术语表 | 明确“收录、安装、发现、验证”并非同一状态 | 术语变化时维护 glossary，不写成任务日志 |
| 不强制完整工作流 | 小任务应该比流程更轻 | 只有真正跨阶段、跨会话时才升级为规格与工单 |

## 文档职责

| 文件 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| `README.md` / 中文版 | 选择入口、最短安装路径、关键状态 | 所有内部配置细节 |
| `doc/usage/quickstart.md` / 中文版 | 安装范围、命令、发现验证、更新与排错 | 证明模型任务质量 |
| `doc/usage/skill-matrix.md` | 按问题路由到 Skill | 强制一次安装全部内容 |
| `doc/usage/matt-pocock-workflow.md` | 维护者操作路径和完成标准 | 重写上游指令 |
| `AGENTS.md` | 常驻仓库约定、按需文档指针、测试命令 | 完整用户手册 |
| `CONTEXT.md` | 项目术语的唯一解释 | 设计细节、待办和进度日志 |
| `upstream.json` | 上游地址、固定版本、文件和依赖记录 | 当前机器安装状态 |
| Git 历史 / CHANGELOG | 实际改动与用户可见变化 | 未执行计划的“完成证明” |

## Matt Pocock 方法的具体借鉴

- [domain-modeling](../../collections/mattpocock/skills/engineering/domain-modeling/SKILL.md)：在概念确实明确后写术语表；当前只是可逆的文档组织，不另建形式化 ADR。
- [writing-for-agents](../../collections/mattpocock/skills/productivity/writing-for-agents/SKILL.md)：常用规则留在入口，分支细节按需加载；每一步具有可检查的完成条件。
- [tdd](../../collections/mattpocock/skills/engineering/tdd/SKILL.md)：对安装示例和文档检查这两个明确边界验证成功/失败场景，纯文字更新不强加测试先行仪式。
- [implement](../../collections/mattpocock/skills/engineering/implement/SKILL.md)：围绕已明确的交付执行相关检查，再报告实际结果。

这些是来源和适配依据，不表示本仓库已经安装或执行了所有列出的 Skill。

## 验收与验证边界

- 英文首页与中文页互链，文档入口可到达 quickstart、选择指南与设计说明。
- 安装示例明确用户级与项目级目录，从真实快照复制完整文件、许可证和来源记录。
- 安装示例在临时目录实测；已有目标与失效软链接必须使安装失败，且不改动原目标。
- 原始快照不变；`.gitignore` 等用户已有修改不纳入无关提交。
- 所有仓库测试通过。未启动 Codex、未验收 UI 组件运行、未确认的授权继续如实标明。

## 后续扩展条件

只有在实际反复需要时才增加功能：多次安装维护困难时考虑安装工具；跨会话工作经常丢上下文时增加真实 handoff；长期任务需要跟踪时完成上游 tracker setup。每次扩展先说明它消除了什么重复工作，而不是先增加目录和配置。
