# Matt Pocock 个人工作流

这不是另一套必须逐关通过的流程，而是本仓库按任务选择 Matt Pocock Skills 的用法。安装步骤见[快速开始](../zh/quickstart.zh-CN.md)，设计理由见[工作流设计](../design/personal-skill-workflow-design.md)。

## 先按任务选择路径

| 任务 | 路径 | 完成标准 |
| --- | --- | --- |
| 修改文案、补链接、修正安装示例 | 直接修改 → 检查 | 内容正确、链接有效；涉及命令时实测命令 |
| 实现一个已明确的小功能 | 明确验收 → implement；行为变化按需用 tdd | 验收条件满足，相关测试通过 |
| 目标或取舍不明确 | grilling → 简短规格 → implement | 决策已明确后停止提问，开始交付 |
| 多阶段功能或跨会话协作 | 规格 → 必要时 to-spec / to-tickets → 分段实现 | 每段可独立验收，有明确阻塞关系 |
| 修改 Agent 指令、术语或设计 | writing-for-agents / domain-modeling | 指令短、术语一致，决策有具体理由 |
| 未完成任务要切换会话 | handoff | 留下当前事实、验证证据和下一步，不复制聊天记录 |

这些是本仓库的选择规则，不修改上游 Skill 指令。实际调用前先阅读该 Skill 的前置条件；当前 Agent 未加载某个 Skill 时，不声称已经调用它。

在 Codex 中用 `$skill-name` 显式选择已安装的 Skill，例如 `$implement` 或 `$handoff`；其他 Agent 使用其对应调用机制。上游 `implement` 包含审查和提交步骤，并非只读建议工具，调用前确认提交范围；仅暂存任务相关文件，不包含用户无关修改。

## 一次实践的最小闭环

1. **写清目标。** 说明要改善什么，以及不做什么。能用三条验收标准说清楚，就不强制开工单。
2. **选一个主 Skill。** 先解决当前瓶颈，不一次装完或调用整套系列。
3. **检查真实文件。** 以仓库内容为证据，区分快照、安装副本和用户改动。
4. **完成交付并验证。** 修改检查器或命令时，先确认测试边界，再验证失败与成功场景；纯文案改动不强制 TDD。
5. **留下必要记录。** 用户指南记用法，设计文档记取舍，CHANGELOG 记可见变化。只有未完成且需交接的任务才写 handoff。

一次实践结束时，应能回答：“改了什么？如何验证？还有什么没验证？”仅仅新增配置文件不算实际使用效果。

## 本仓库的真实示例：补齐安装文档

- **目标**：英文首页和中文入口都能引导读者安装一个 Skill。
- **范围**：用户级/项目级路径、可复制命令、选择指南、维护约定；不自动安装到真实用户目录。
- **方法**：使用 `implement` 执行明确需求；参考收录的 `domain-modeling` 定义“快照/安装副本”，参考 `writing-for-agents` 将细节移到按需文档。这不等于已将所有参考 Skills 注册到当前 Agent。
- **验证边界**：从 Markdown 提取 Bash 示例，在临时 HOME 和项目目录运行；检查完整文件、许可证和来源记录；重跑不得覆盖，失效软链接不得被跟随。
- **证据入口**：[文档测试](../../tests/test_documentation.py)及 `python3 -B -m unittest discover -s tests -v` 的实际结果。
- **未覆盖**：Codex 客户端实际发现、任务输出质量、第三方组件运行效果；不能用文件复制测试替代这些验证。

## 工单和上游 setup 的边界

GitHub Issues 是将来需要远程跟踪时的目标：`Kris4js/awesome-skills`。普通文档修订不自动创建 Issue。

本仓库尚未完成上游 `setup-matt-pocock-skills` 的全套配置，且没有 `docs/agents/issue-tracker.md`。如需原样运行依赖它的 `to-spec`、`to-tickets` 或正式双轴 `code-review`，先完成对应配置和权限确认；不要把本指南当成这些文件已存在，也不要静默改变上游默认路径。

日常实现检查不以全套 setup 为前提。已有明确需求时直接工作；未要求发布 Issue 或推送时，不用流程替用户扩大操作范围。

## 维护约定

- 根 `README.md` 是英文首页，`doc/zh/README.zh-CN.md` 是对应中文版本；同一次改动同步范围、命令、数量和状态。
- 安装细节分别放在英文与中文 quickstart。其安装代码由测试直接执行，避免示例与实际脱节。
- `AGENTS.md` 只放导航、保护边界和验证命令；`CONTEXT.md` 只放术语，不写任务流水账。
- `doc/design/` 保存本仓库的设计说明，不复制其他项目的记忆体系。必要时才增加实际交接记录，不预建空目录。
- 上游快照保持原文。修改来源、版本或许可状态时，同步相应 `upstream.json`、指南与测试。
